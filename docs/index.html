One connection to every MCP server.

mcpgate sits between your AI app and the MCP servers you use. The app sees five tools instead of hundreds, and finds the right one by searching. You manage everything from a web page on your own computer.

Your app gets five tools. Everything else is a search away.

Every MCP server you add normally puts all of its tool descriptions in front of the model, whether it needs them or not. mcpgate keeps them behind the gateway. The model asks for what it wants in plain words, gets back the few tools that match, and calls one.

list_backends

Which servers are connected, and which can be reached right now.

search_tools

Find a tool by describing what you want, across every server at once.

describe_tool

Show the full arguments of one tool, only when the short answer is not enough.

call_tool

Run a tool by its full name, such as github.create_issue. Risky ones wait for you.

read_result

Page through a long result instead of loading all of it at once.

  1. The app searchesIt sends a few words, such as “create github issue”. It does not need to know which server has the tool.
  2. mcpgate answers with matchesThe best tools come back with their names and arguments. Tools you have hidden never appear.
  3. The app calls onemcpgate checks your rule for that tool: allowed, needs approval, or hidden. If it needs approval, the call waits until you approve it on the admin page, where you can see the exact arguments.
  4. The result comes backLong results arrive in pages. Every call is written to the activity log.

Do everything from one page, not a config file.

After the installer finishes you never need the terminal. The admin page runs on your computer only. Add servers, paste a token once, choose what the model may do, and watch what it did.

127.0.0.1:8767
It reacts live

Save a change and it applies within about two seconds. A config with a mistake never replaces the one that works, and the page says what is wrong.

It explains failures

A backend that cannot connect shows a plain reason and a hint, not a stack trace.

It works without a mouse

Keyboard friendly, readable at phone width, light and dark, and checked for contrast and labels by automated tests.

Set it up on one side, connect from the other.

mcpgate runs on a computer you control, usually a laptop or server that stays on. Your AI app connects to it from wherever you chat. Both halves take a few minutes.

On the computer that runs mcpgate

Linux with systemd. Python 3.11 or newer; the installer fetches one if you do not have it.

  1. Install

    This installs the command, starts a background service that survives logout and reboot, and prints a one-time setup code. It opens no network port and never asks for a token.

    git clone https://github.com/Piyushchy/mcp.git
cd mcp
./install.sh
  2. Open the admin page

    Go to http://127.0.0.1:8767 on that computer, enter the setup code and choose a passphrase of at least 12 characters. From another computer, forward the page over SSH first:

    ssh -L 8767:127.0.0.1:8767 you@the-server
  3. Add a server

    Pick GitHub or Google Colab, a remote server by address, or a command that runs on this computer. Paste its token; it is stored write-only and never shown again. Press Test, then choose for each tool whether it is allowed, needs approval, or is hidden.

  4. Only for web apps: give it an address

    Apps such as claude.ai reach mcpgate over the internet. Open Remote access, enter the public address of a tunnel (Tailscale Funnel or Cloudflare), and press Check connection. With Tailscale:

    tailscale funnel status
sudo tailscale funnel --bg 8766

    Funnel publishes on port 443 and replaces whatever it already serves there, so read the status first. If something else uses 443, give the address field a different Funnel port such as :8443.

In the app you chat from

Pick the one you use. Each takes under a minute once mcpgate is running.

  1. Add a custom connector

    In claude.ai open Settings, then Connectors, then Add custom connector. Name it anything and use your public address with /mcp on the end:

    https://your-machine.your-tailnet.ts.net/mcp
  2. Sign in with your approval passphrase

    claude.ai opens a page served by your own mcpgate. Type the approval passphrase you set on the Tokens page and approve. There is no token to paste.

  3. Ask for something

    Say what you want in plain words. The model searches, calls the tool, and anything you marked as needing approval waits for you on the Approvals page.

  1. Claude Code

    On the same computer you need no tunnel and no token:

    claude mcp add mcpgate -- mcpgate serve
  2. Claude Desktop and similar

    Add a server whose command is mcpgate and whose argument is serve. The app starts it and talks to it directly.

  1. Create an access token

    On the Tokens page, press Create token and copy it once. It cannot be shown again.

  2. Add the server to the app

    Apps that take a JSON settings file need the address and one header. Write the word Bearer, a space, then the token. Some apps name the first key url instead of serverUrl.

    {
  "mcpServers": {
    "mcpgate": {
      "serverUrl": "https://your-machine.your-tailnet.ts.net/mcp",
      "headers": { "Authorization": "Bearer YOUR_TOKEN" }
    }
  }
}

    A token typed into a chat, a screenshot or a public file is no longer private. If that happens, create a new one on the Tokens page and delete the old one.

Built so a mistake in one place does not open another.

The gateway holds your tokens and can run programs on your machine, so the design assumes something will go wrong and limits what it can reach. The full reasoning is in the threat model.

The admin page cannot be reached from the network

It listens on this computer only. No setting, flag or environment variable changes that, and the public port has no admin code at all.

Tokens are write-only

You can replace or delete a stored token, but no page, log or error message ever shows it again.

Every change is checked three ways

A signed-in session, a one-time token on each request, and a check of where the request came from. A wrong host name is refused.

Anything that runs code asks again

Adding or changing a command needs your admin passphrase each time, even when you are signed in.

Approvals show the real arguments

When a tool needs your approval you see exactly what it will be called with, and you choose once, for a while, or never.

Private files, strict page rules

Secret and passphrase files are readable only by you and written atomically. The admin page loads no outside scripts and runs no inline code.

What it does not do. Stored tokens are plain text on disk, protected by file permissions rather than encryption. Results from your servers reach the model unchanged. Signing in to a server with an account is tested against a local test server, not yet against every real service, and the Colab backend is experimental. This is version 0.1.

Questions

Do I have to open a port on my router?

No. The admin page never leaves your computer. For web apps you use a tunnel such as Tailscale Funnel or Cloudflare, which connects out from your machine, so nothing listens on your network.

Which apps can connect?

mcpgate speaks standard MCP, so any app that supports MCP over HTTP or as a local command can use it. claude.ai is the one it was developed against; the setup steps for Claude Code, Claude Desktop and apps with a JSON settings file are above.

A server I want signs in with an account, not a token. Can it do that?

Yes. Add it as a remote server, tick This server needs me to sign in with an account, then press Sign in on its card. The server’s own login page opens, and mcpgate keeps the resulting login in a private file and refreshes it. Sign out forgets it.

Can I add my own tools?

Yes. Put a Python file in the custom folder and it becomes a server, or run mcpgate new for a template. Adding a command always asks for your admin passphrase, and the whole feature can be switched off in Settings.

Where are my tokens stored?

In a file on your computer that only your user can read. They are not encrypted, they are write-only in the interface, and they are kept out of logs and error messages.

How do I update or remove it?

Run ./install.sh again to update; your settings, tokens and sign-ins are untouched. ./install.sh uninstall removes the service and the command.

Why does Colab need extra steps?

Google’s Colab server works by having the Colab page in your browser connect back to the computer that runs it. If your browser is on a different computer, mcpgate gives the model a link and the one SSH command that makes the connection possible. It is experimental.
